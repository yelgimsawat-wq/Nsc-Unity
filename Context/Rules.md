# Rules — workflow ขอบเขตงาน และเกณฑ์จบ

กติกาการสนทนาและการอ่านอยู่ที่ [../AGENTS.md](../AGENTS.md) ส่วน template และสถานะ Quest อยู่ที่ [Agent-Handoff.md](Agent-Handoff.md)

## ก่อนเริ่มงาน
1. ทำตามลำดับเริ่ม session ใน [../README.md](../README.md)
2. งานที่จะแก้ไฟล์ต้องมี Quest ถ้ายังไม่มีให้สร้างก่อนแก้ไฟล์อื่น งานถาม ตอบ อ่าน หรือวิเคราะห์ที่ไม่แก้ไฟล์ไม่ต้องมี Quest
3. เทียบ Files ของ Quest ที่เปิดอยู่ทั้งหมดกับไฟล์ที่จะแก้ ถ้าทับกันให้ทำตามหัวข้อหลาย agent ด้านล่าง

## ขอบเขต
- แก้เฉพาะ path ที่อยู่ใน Files ของ Quest ตัวเอง ถ้าต้องแก้เพิ่ม ให้เพิ่ม path ใน Quest และตรวจการทับซ้อนก่อน
- ไม่ commit, push หรือสร้าง branch เว้นแต่ผู้ใช้สั่ง
- การจัด Context ไม่เปลี่ยนนโยบาย build, test หรือ deploy ของเกม และไม่รัน build/deploy ถ้างานไม่ได้เปลี่ยนเกม

## หลาย agent
- เริ่ม agent เพิ่มเมื่อผู้ใช้สั่งเท่านั้น
- แต่ละ Quest มี Owner ชัดเจน
- ก่อนแก้ไฟล์ ตรวจ Files ของ Quest ที่เปิดอยู่ ถ้า scope ทับกัน ให้ถามผู้ใช้ว่าใครเป็นเจ้าของส่วนที่ทับก่อนแก้
- ไม่แก้ ปิด หรือยึด Quest ของ agent อื่นเอง เปลี่ยน Owner เมื่อผู้ใช้สั่งให้รับช่วงเท่านั้น
- ก่อนอัปเดต Quest ให้อ่านไฟล์ล่าสุดแล้ว patch เฉพาะส่วนของตัวเอง ไม่เขียนทับจาก snapshot เก่า
- ห้ามถือว่างานถูกทิ้งเพราะเวลาผ่านไป

## ตรวจตามชนิดการเปลี่ยนแปลง
เริ่มจากแถวที่เล็กที่สุดที่ครอบคลุมงาน ขยายเมื่อผลตรวจพบปัญหาหรือกระทบระบบร่วม

| เปลี่ยนอะไร | ตรวจขั้นต่ำ |
|---|---|
| เอกสาร / Context | ลิงก์ relative ชี้ไฟล์ที่มีอยู่จริง และไม่ขัดกับเอกสารเจ้าของ |
| C# script | compile ผ่าน: Unity Console ไม่มี error หรือ `dotnet build Assembly-CSharp.csproj` (csproj ที่ Unity generate ไว้ ไม่อยู่ใน git ถ้าเก่ากว่าโครงโฟลเดอร์ปัจจุบันให้ Unity regenerate ก่อน) |
| logic ที่มี EditMode test | Unity Test Runner เฉพาะ test ที่เกี่ยวข้อง (`Assets/_Game/Editor/Tests/`) |
| scene, prefab, networking | Play Mode โหมดที่กระทบ (วิธีทดสอบหลายเครื่องอยู่ใน [../CLAUDE.md](../CLAUDE.md)) |
| `tools/context/*.py` | รันจริงกับโฟลเดอร์ชั่วคราวผ่าน `--context-dir` |

ผลตรวจที่ไม่ได้รันใน session นี้ต้องเขียนว่ายังไม่ได้ตรวจ หรืออ้างวันที่และที่มาเดิม

## จบงานหรือหยุดส่งต่อ
1. ตรวจให้ตรงชนิดการเปลี่ยนแปลง
2. อัปเดต Quest: Validation (ผลจริง), ข้อจำกัด, Next action
3. ถ้าแก้ไฟล์ เขียน Edit Log หนึ่งรายการ (หัวข้อถัดไป)
4. ผ่านครบ ตั้ง `ready-to-close` แล้วเสนอปิดด้วย Quest ID ถ้ายังไม่ครบ ตั้ง `waiting` หรือ `blocked` พร้อมสิ่งที่ขาด
5. ย้าย Quest เข้า `Context/archive/quests/` เมื่อผู้ใช้ยืนยัน หรือเมื่อผู้ใช้สั่งปิดไว้แล้วและผ่านเกณฑ์ครบ ปิดเฉพาะ Quest ที่ได้รับคำสั่ง ไม่เหมาทั้ง Board
6. ก่อนย้ายไฟล์ ตรวจ path ที่ resolve แล้วว่า source อยู่ใน `Context/quests/` และ target อยู่ใน `Context/archive/quests/`

## Edit Log
```
python tools/context/log-edit.py --quest Q-ID --files "path/a, path/b" --summary "แก้อะไรและเพราะอะไร" --validation "ผลตรวจและข้อจำกัด"
```
- บันทึกหนึ่งรายการเมื่อจบหรือหยุดส่งต่องาน ไม่บันทึกทุกครั้งที่เซฟ
- Quest ID ซ้ำจะอัปเดตรายการเดิม (รวม files, แทน summary/validation)
- เก็บ 10 งานล่าสุดใน [Edit-Log.md](Edit-Log.md) งานละ 3 บรรทัด รายการเก่ากว่าย้ายเข้า `archive/edit-log/YYYY-MM.md` อัตโนมัติ
- ถ้าติด lock สคริปต์จะรอและลองใหม่เอง ถ้าหมดเวลาให้รอแล้วรันใหม่ ห้ามลบ lock ของ agent อื่น ถ้าสงสัยว่า lock ค้างให้ถามผู้ใช้
- ห้ามใส่ secrets, tokens, passwords หรือ path ส่วนตัว สคริปต์ปฏิเสธ input ที่ดูเหมือน secret

## โน้ตหัวข้อสนทนาล่าสุด
- `CURRENT_TOPIC_PATH` = ค่าจาก environment variable `CURRENT_TOPIC_PATH` ถ้าตั้งไว้ ไม่เช่นนั้นใช้ `~/Notes/ChatGPT-Current-Topic/latest.md` (นอก repo แยกตามเครื่อง ห้ามใส่ path จริงของเครื่องใดลงเอกสารที่แชร์)
- agent ที่คุยกับผู้ใช้โดยตรงเป็นผู้ดูแล background agent ห้ามแก้
- เนื้อหา: โน้ตภาษาไทยสั้น ๆ มีหัวข้อล่าสุด บริบทสำคัญ การตัดสินใจ และ next action
- อัปเดตเมื่อเปลี่ยนหัวข้อหรือมีการตัดสินใจสำคัญ โดยแทนเนื้อหาเดิม ไม่ต่อ transcript ไม่สร้างประวัติสำรอง
- ก่อนตอบหรือทำงานใน voice session ใหม่ (รวมการเปิด voice ใหม่ใน chat เดิม) ให้อ่านไฟล์นี้ก่อน อ่านเฉพาะ `latest.md` ไม่อ่านทั้งโฟลเดอร์
- ใช้เป็นบริบท ไม่ใช่คำอนุญาตให้ทำงานเก่าต่อ
- ถ้าอ่านหรือเขียนไม่ได้ ให้แจ้งข้อจำกัดโดยไม่แต่งบริบทขึ้นเอง
- ไม่อ้างว่าซิงค์กับเว็บ มือถือ หรือแอปอื่น ถ้ายังไม่ได้เชื่อมจริง
